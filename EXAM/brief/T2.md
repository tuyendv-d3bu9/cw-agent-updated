# T2 — Create a new agent: requirement → test traceability audit

Rubric: **A3** (14 pts), parts of **A1**, **A6**, and the instructor criteria. See [RUBRIC.md](RUBRIC.md).

## 1. Requirement

Create a **new agent folder** `qa-system/qa-<name>/` (you choose `<name>`, lowercase kebab-case) whose
skill audits **requirement → test traceability** for a task:

| Item | Requirement |
|---|---|
| Path | Governance decision `[B]` (new agent), all **7 anchors N1–N7** handled, plus the `[B]`-only items B-a … B-f (governance §4) |
| `AGENT.md` | Built from `qa-system/templates/AGENT.md`; **no `<…>` placeholder left**; has the `Human-Final` section and the `Knowledge` section (default: writes nothing) |
| Skill | `qa-system/qa-<name>/skills/<skill>.md`, built from `qa-system/templates/skills/ten-skill.md`; frontmatter `name` + `description`; inputs, steps, acceptance gate |
| Skill inputs | Reads `OUTPUT/<task-slug>/01_requirement_risk_summary.md` and `OUTPUT/<task-slug>/05_test_case_spec.md` (plus `knowledge/_project.md` and `knowledge/features/<slug>.md`, QA_STANDARD §7) |
| Skill output | Exactly one file: `OUTPUT/<task-slug>/17_<snake_name>.md` (`17` is the next unused prefix in `WORKFLOW.md` §2; `<snake_name>` is lowercase snake_case that you choose) |
| What it audits | For every requirement id in 01 (`BR`, `FD`, `AF`, and confirmed `MR` where used), which test cases in 05 trace to it; requirements with no test case; test cases that reference an id that does not exist in 01 (orphans) |
| `## Format output` | The skill **must** contain a section `## Format output` that lists **every required heading** of the deliverable (and the meta line on line 2 per QA_STANDARD §7). The example output is checked against this list |

## 2. Registration (all five are checked)

| # | File | What to add |
|---|---|---|
| 1 | `knowledge/_system_map.json` → `specialized_agents` | The new agent (path, role, skills path) |
| 2 | `knowledge/_system_map.json` → `routing_table` | Route to the new skill |
| 3 | `qa-system/workflows/WORKFLOW.md` | Row in the §2 table (`# · Agent · Skill · In · Out`) with prefix `17`; §1 if you open a new branch |
| 4 | `qa-system/qa-lead/AGENT.md` | Row in the routing matrix (§2) **and** a row in the natural-language mapping table (§5) |
| 5 | `qa-system/tools/system/agent-doctor.js` | Node in `PIPELINE_DEPENDENCIES` (`skill`, `produces`, `consumed_by`) |

Also update `qa-system/README.md` (governance B-e). If you change a tool (for example
`agent-doctor.js`), add a test for that change under `qa-system/tools/__tests__/` (rubric A6a).

## 3. Run it once

Run your new skill **once** on `shopgo-refund`, after your T3 stage 05 exists, to produce the example
output `OUTPUT/shopgo-refund/17_<snake_name>.md`. The example output must contain every heading your
`## Format output` declares.

## 4. Acceptance

- `npm run agent:check` prints **`INTACT`**.
- `npm run agent:check -- --impact <your-agent>` resolves your agent with at least one edge.
- `npm test` is green.

Paste the **real** output of these commands (shortened) into `EXAM/DECISIONS.md` section `## t2`.

## 5. What to record

| Where | Content |
|---|---|
| `EXAM/DECISIONS.md` section `## t2` | The A/B/C decision table (why `[B]`), the layer table, the anchor table N1–N7 and B-a … B-f, the real gate results |
| `EXAM/submission.json` → `t2_new_agent` | `agent_folder`, `agent_file`, `skills`, `deliverable_prefix` (`17`), `example_output`, `registrations` (every file you registered in), `tests_added`, `decision_record` (`EXAM/DECISIONS.md#t2`) |

## 6. Done when

- [ ] `qa-system/qa-<name>/AGENT.md` and `skills/<skill>.md` exist, no `<…>` placeholders left.
- [ ] Registered in all five places of §2 and in `qa-system/README.md`.
- [ ] `OUTPUT/shopgo-refund/17_<snake_name>.md` exists and contains every heading of `## Format output`.
- [ ] `npm run agent:check` → `INTACT`; `--impact` resolves the agent; `npm test` green.
- [ ] `EXAM/DECISIONS.md#t2` and `EXAM/submission.json` are filled in and consistent.
