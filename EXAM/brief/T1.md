# T1 — Customise an existing agent: mandatory `Risk Ref` on every test case

Rubric: **A2** (12 pts), parts of **A1**, **A6**, and the instructor criteria. See [RUBRIC.md](RUBRIC.md).

## 1. Requirement (same for every student)

Customise agent `qa-test-design`, skill `test-case-generation`
(`qa-system/qa-test-design/skills/test-case-generation.md`), so that:

1. **Every test case has a new mandatory field `Risk Ref`.**
2. The value of `Risk Ref` is either
   - **one or more `RK-xx` ids** taken from the risk table of
     `OUTPUT/<task-slug>/01_requirement_risk_summary.md`, separated by `, ` (comma + space), for example
     `RK-01` or `RK-01, RK-04`; or
   - **`N/A — <reason>`** when no risk in 01 applies: the literal `N/A`, a space, an em dash `—`
     (U+2014), a space, and a non-empty reason, for example `N/A — <why no risk in 01 applies>`.
3. The field is written in the test case block in the same style as the other fields:

   ```markdown
   - **Risk Ref**: RK-01, RK-04
   ```

   This applies to `05_test_case_spec.md` **and** to every `testcases/batch_NN.md`.
4. The lint (`qa-system/tools/system/lint-deliverables.js`, governance anchor **N7**; parser helpers in
   `qa-system/tools/lib/schema.js` if you need them) reports an **error** (exit `1`) when:
   - a test case has no `Risk Ref` field, or the field is empty;
   - a `Risk Ref` value is neither a list of `RK-xx` ids nor `N/A — <reason>` with a non-empty reason;
   - a referenced `RK-xx` id does not exist in that task's `01_requirement_risk_summary.md`.

   A test case with a valid `Risk Ref` must not produce a new error or warning.
5. **Tests**: add test cases under `qa-system/tools/__tests__/` that prove the lint change: at least one
   valid sample that passes and one sample for each error case above. `npm test` must stay green.
6. The skill's documentation is updated consistently: the field list ("8 fields" table), the value rules
   (where the value comes from and what to write when it is missing), the `## Format output` example and
   the acceptance gate (`## Chốt chặn nghiệm thu (Quality Gates)`).
7. Any other file that reads, writes or merges test case fields must keep `Risk Ref` working (check this
   yourself — for example the batch merge and the blueprint).

## 2. How you must work

Follow `qa-system/qa-lead/skills/system-upgrade-governance.md` — do not improvise.

1. **Classify** the request with the decision tree `[A] / [B] / [C]` (governance §1). Answer all three
   questions with a one-line reason each. The class is your decision; it is graded for consistency with
   the files you changed, not against a hidden answer.
2. **Place each change in the right layer** (governance §2).
3. **Propagate to the 7 anchors N1–N7** (governance §4). For every anchor write `done` or `n/a`. Every
   `n/a` needs a reason of at least one sentence.
4. **Run the acceptance gate** (governance §5): `npm test` and `npm run agent:check`, and paste the
   **real** output (shortened) into your decision record.

## 3. What to record

| Where | Content |
|---|---|
| `EXAM/DECISIONS.md` section `## t1` | The A/B/C decision table, the layer table, the anchor table N1–N7 (`done` / `n/a` + reason), the real gate results |
| `EXAM/submission.json` → `t1_customized_agent` | `agent_folder` (`qa-system/qa-test-design`), `decision_class`, `changed_files`, `anchors` (N1–N7: `done` / `n/a`), `anchor_reasons` (one entry per `n/a`), `tests_added`, `decision_record` (`EXAM/DECISIONS.md#t1`) |

Every anchor marked `done` must match a real change in `changed_files`. Every file in `changed_files` must
lie in a layer allowed for the class you declared.

- [ ] `npm run agent:check` prints `INTACT`.
- [ ] `EXAM/DECISIONS.md#t1` and `EXAM/submission.json` are filled in and consistent with each other.
- [ ] Your own `05_test_case_spec.md` in T3 uses `Risk Ref` on every test case and passes lint.
